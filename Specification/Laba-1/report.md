**Дисциплина:** оценка качества ПО. **Работа:** `Specification/Laba-1.md`.
**Выполнил:** Мороз Роман, ПВ-233. **Дата:** 26.11.2026.

## Цель и проблемы разработки

Измерить размер, сложность, покрытие и наблюдаемую дефектность небольшого
проекта; связать измерения с корректностью, надёжностью и трудоёмкостью.

| Проблема | Последствия | Решение | Методы и инструменты |
|---|---|---|---|
| Неоднозначные требования и неверные входные данные | Разработчик и тестировщик получают разные ожидаемые результаты | Явный контракт, критерии приёмки, классы эквивалентности | Таблицы решений, pytest parametrization, review требований |
| Рост связности и сложности | Исправление одного места ломает другие, увеличивается время анализа | Чистая бизнес-логика, разделение слоёв, ограничение ответственности | Radon CC, LOC/SLOC, code review, unit и integration |
| Невоспроизводимая сборка и регрессии зависимостей | Один и тот же код ведёт себя по-разному на машинах | Lockfiles, версии инструментов, CI и security gates | uv, Cargo, npm ci, Bandit, pip-audit, cargo-audit |

## Проект и контракт

Объект измерения — [`calculator.py`](calculator.py), независимый от сети
и глобального состояния Python-модуль, как прямо требует задание.
`calculate(left, operator, right)` поддерживает `+`, `-`, `*`, `/` и возвращает
`float`. При делении на ±0 — `ZeroDivisionError`; неверной операции или
не конечном числе — `ValueError`; строках, контейнерах и bool — `TypeError`;
не конечном результате — `OverflowError`. Огромный Python int, который не
представим как float, также может вызвать `OverflowError` при проверке конечности.
Это вычислитель для учебных чисел, не денежный движок с десятичной точностью.

33 теста калькулятора проверяют четыре операции, ноль, отрицательные и дробные
числа, переполнение, типы, обе позиции NaN/∞, деление на положительный и
отрицательный ноль. 34 теста доставки служат вторым объектом сравнения.
Задачи проекта заведены в [доске](../Total/kanban.md): Q-01—Q-05. Это собственная
таблица Kanban, разрешённая общим заданием; внешний трекер не создан.

## Воспроизведение измерений

```bash
uv sync --locked --dev
uv run --locked pytest -v --cov --cov-branch --cov-report=xml:artifacts/python/coverage.xml
uv run --locked radon raw -s Specification/Laba-1/calculator.py TestingPS/Laba-1/delivery.py
uv run --locked radon cc -s Specification/Laba-1/calculator.py TestingPS/Laba-1/delivery.py
uv run --locked python Specification/Laba-1/scripts/metrics.py
```

Машиночитаемый снимок — [metrics.json](evidence/metrics.json),
проверки — [python-tests.txt](../../docs/evidence/python-tests.txt).
LOC включает все физические строки; SLOC — строки кода без комментариев,
docstring и пустых строк. Поэтому число исполняемых строк coverage отличается
от LOC и SLOC; сравнивать эти показатели как одинаковые нельзя.

| Модуль | LOC | SLOC | CC функции | Строки | Ветви | Найдено дефектов | Дефекты/KLOC SLOC | Время реакции |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| Калькулятор | 27 | 22 | 11, C | 100% | 100% | 0 | 0 / 0,022 = 0 | не измерялось |
| Расчёт доставки | 28 | 16 | 7, B | 100% | 100% | 0 | 0 / 0,016 = 0 | не измерялось |

Дефекты внешнего Restful-Booker учитываются отдельно: они не принадлежат коду
калькулятора и не включаются в его плотность дефектов. Отсутствие найденных
дефектов означает только результат выполненного набора проверок.
Время исправления дефектов и трудозатраты не выдумываются: замеров не было.

## Цикломатическая сложность

Для доставки: шесть условий (`amount < 0`, `distance < 0`, `amount >= 5000`,
`distance <= 5`, `distance <= 20`, `premium`), поэтому `V(G) = 6 + 1 = 7`.
При графе из 6 узлов решений, 7 линейных блоков и 1 общего выхода получаем
`N = 14`, `E = 19`, `P = 1`: `19 − 14 + 2 = 7`.

Для калькулятора Radon учитывает также цикл и `or`: начальная 1 + цикл 1 +
проверка типа 1 + `or` 1 + конечность входа 1 + выбор четырёх операций 4 +
деление на ноль 1 + конечность результата 1 = **11**.
Правила подсчёта приведены в [документации Radon](https://radon.readthedocs.io/en/latest/intro.html).

## Вывод

Корректность оценивается через явный контракт и ожидаемые результаты;
надёжность — через отклонение ошибочных входов и воспроизводимость.
Сложность 11 у маленького калькулятора в основном связана с валидацией:
при росте операций разумно выделить её и таблицу операций. Покрытие 100%
подтверждает выполнение строк и исходов условий, но не полноту требований.
Чистые функции и параметризованные тесты уменьшают трудоёмкость изменений;
количественную экономию времени без измерений установить нельзя.
