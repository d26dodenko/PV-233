**Цель:** Освоить практические методы оценки качества и метрик программного обеспечения.

## Часть 1. Теоретическая

### 1. Три наиболее значимые проблемы при разработке сложных программных систем

**1) Рост сложности и связанности архитектуры.**
С увеличением размера системы число компонентов и связей между ними растёт быстрее, чем сам код. Разработчик не может удержать в голове всю систему, изменение в одном месте непредсказуемо ломает другое, код становится трудно читать и сопровождать.

**2) Изменчивость и неполнота требований.**
Заказчик часто не может сразу точно сформулировать, что ему нужно, а требования меняются в ходе проекта. Это приводит к переделкам, срыву сроков и росту трудоёмкости, а итоговый продукт может не соответствовать реальным потребностям пользователей.

**3) Обеспечение качества, корректности и надёжности.**
В сложной системе невозможно проверить все сочетания входных данных и состояний. Дефекты остаются незамеченными до эксплуатации, а их исправление на поздних этапах стоит многократно дороже, чем на ранних.

### 2. Таблица «Проблема → Возможное решение → Инструменты/методы»

| Проблема | Возможное решение | Инструменты / методы |
|---|---|---|

### 7. Цикломатическая сложность

**Калькулятор (Python)**, команда `radon cc -s calculator.py`:

```
calculator.py
    F 23:0 calculate - B (6)
    F 38:0 classify_number - A (3)
    F 13:0 divide - A (2)
    F 1:0 add - A (1)
    F 5:0 subtract - A (1)
    F 9:0 multiply - A (1)
    F 19:0 power - A (1)
```

Средняя сложность: (6 + 3 + 2 + 1 + 1 + 1 + 1) / 7 = 15 / 7 ≈ **2.14**.

**Разбор функции `calculate`** (наибольшая сложность в модуле):

```python
def calculate(a, op, b):
    if op == "+":
        return add(a, b)
    elif op == "-":
        return subtract(a, b)
    elif op == "*":
        return multiply(a, b)
    elif op == "/":
        return divide(a, b)
    elif op == "**":
        return power(a, b)
    else:
        raise ValueError(f"Неизвестная операция: {op}")
```

*Расчёт через условия:* проверок 5 (`op == "+"`, `"-"`, `"*"`, `"/"`, `"**"`), поэтому

V(G) = 5 + 1 = **6**

*Расчёт через граф потока управления:*
- узлов N = 12 (5 узлов-проверок, 5 узлов `return`, 1 узел `raise`, 1 выходной узел);
- рёбер E = 16 (по 2 ребра из каждой проверки = 10, плюс 6 рёбер от `return`/`raise` к выходу);
- компонент P = 1.

V(G) = E − N + 2P = 16 − 12 + 2 · 1 = **6**

Оба способа и результат `radon` совпадают.

**ServerService.java (Java)**, по данным lizard (колонка CCN): максимальная сложность у метода `changeNameOrAvatar` — **5**; `getServer` и `getUsersOnServer` — по 3; средняя сложность по модулю — **2.2**. Предупреждений о превышении порога (CCN > 15) нет.
